# Appendix E: Retrieval on two devices

**Post-hoc and exploratory**, governed by pre-registration amendment
1.32.2 as corrected by 1.32.6. The question was not registered; it was
raised by pulling the repository onto the Raspberry Pi 5 after every
hypothesis was already decided. **No threshold is applied, no verdict
is reached and no hypothesis is revisited.**

Generated by `scripts/compare_index_architectures.py` from committed,
authenticated runs. Every count below is computed by that script and
none is typed. No measurement was taken for this appendix: it compares
evidence that already existed.

## E.1 What is compared, and what is not

`data/index.json` is a build artefact and is **not** in the repository.
Each machine builds its own from the committed corpus. The two device
builds are not the same file:

| | Serialised index file |
|---|---|
| Authoring laptop | `8045d1d46736978e8bf67d45f4a5ef5a7273925143186a91c32d983d9ab7333d` |
| Raspberry Pi 5 | `9b5053fb2eff3bd1429626b4882a4accde60091577f1a277e1a05165dcec39ce` |

**That is the whole of what those hashes establish: the two serialised
index files differ.** Nothing in this appendix reads either index file
or compares a single vector, so no claim is made here about how they
differ, by how much, or why. The corpus and chunk-set fingerprints
agree, which establishes equivalent chunk identifiers, sections and
text under those fingerprints' definitions; it does not establish that
the serialised records are byte-identical.

Each device also embedded every **query** locally. What is compared
below is therefore the observed retrieval output of two device-local
embedding and retrieval pipelines, not the stored index vectors alone.

## E.4 What this does and does not affect

**H1 to H4 are unaffected.** They are scored entirely on the four
frozen quality runs, all executed on the authoring laptop over one
index. The Pi runs are performance-only under amendment 1.15 and
contribute no quality figure to any hypothesis.

**H5 is a ratio measured within the Pi**, where both arms used the same
Pi-built index, so the comparison is internally consistent. The caveat
is stated rather than omitted: on 3 of 68 questions
the Pi generated from marginally different evidence than the laptop
did, so its absolute latencies are not strictly a measurement of the
laptop's workload.

**What it supports about deployment**, and no more: the artefact
reproduces its retrieval substrate on the target device from the corpus
alone rather than shipping a prebuilt index, and the substrate it
reproduced returned the same evidence on 66 of 68
questions in this one comparison. That is an observation over one
corpus, one device pair and one question set.
